# Independent review and offline baseline adapters

This is the complete **provisional disabled source package** for combined S02–S03. It does not enable security review or run a scanner. Source-authoring order was amended by the owner; S01 acceptance and every qualification/activation gate remain intact.

## What is implemented

- Immutable native invocation plans and a single unconditional execution refusal. There is no enabled flag, executor callback, installation, provider client, shell, subprocess or raw-source fallback.
- External policy and asset-document loaders using S01's outside-candidate pinned-reference boundary. Unknown binary/rule/database pins are refused rather than invented.
- Virtual read-only scanner layouts from explicitly selected S01 original bytes. Model review uses only S01 ModelBundle/Broker data.
- A sanitized synthetic Git projection for OCR preview/rule operations. It enumerates the review inventory as additions and does not pretend to reproduce the target's original Git diff. Native selection is reconciled against the independent inventory.
- Independent-context chunk handoffs, mandatory JSON-value/policy-content topics, deep/surface/skipped/missing accounting, source-to-sink finding evidence and unresolved false-positive challenges.
- Explicit local-rule Opengrep, fully redacted Gitleaks CLI and preloaded offline OSV plans. Gitleaks files, stdin and bounded synthetic snapshot-history modes are represented; no host .git or unselected historical objects are used.
- Strict bounded output parsing and private S01-schema evidence normalization. Unsafe native messages, snippets, secret fields and Git metadata are not forwarded. Empty reports do not imply coverage.
- Synthetic positive/negative/adversarial fixtures, authored unit tests, separate procedure attribution and both rollback procedures.

## Layout and API

Add security-integration/s01 and security-integration/s02-s03 to the trusted application's Python import path. The package imports the preserved S01 data/validation interfaces without changing them. Do not execute candidate imports in a model context with filesystem privileges. The model receives only the handoff document/Broker surface, never Snapshot, Views.private_evidence, original_history, asset bytes or normalized private results.

The preparation flow is: load an explicitly pinned external policy and inventory; accept an S01 selected snapshot and its separately approved model release; build sanitized handoff or disabled native plan; produce an in-memory read-only layout. All run entry points unconditionally raise provisional_execution_disabled. The preparation flow itself grants no permission to read additional paths or mount/run the resulting bytes.

The result flow is: receive bounded native bytes and the actual externally retained execution receipt; normalize only whitelisted evidence; supplement coverage only from a separately pinned independent per-run coverage receipt. S01 target acceptance is never invoked or declared. The generic aggregate is a state summary, explicitly not verified coverage.

Native execution evidence and independent coverage receipts both require `plan_sha256`, equal to the exact disabled invocation plan's `identity`. Normalizers reconstruct that plan for the requested adapter, mode and target selection. This binds stdin item selection, synthetic history projection, explicit lockfile parsers and declared asset pins as well as the snapshot and adapter policy. Receipts without this field, or with a different plan identity, are refused; they must be regenerated by the external evidence producer, never patched in place to match a desired invocation. Computing a plan identity is not execution evidence or permission. Gitleaks stdin coverage is restricted to its one selected item; all other snapshot items remain uncovered.

## Current hard limits

S01 presently supports a synthetic static-fixture runner only and its containment acceptance remains held. Real OCR/scanner execution, dynamic runtime closure, isolated Git execution and the new mount layout are **not implemented as an active runner or qualified** here. The provisional adapters' invocation/layout/parsing interfaces are complete, but lifting the unconditional execution refusal requires a separate coherent reviewed implementation and qualification of that boundary, not toggling a configuration bit.

The engine binary pins, production rulepack pins, OSV database pins, asset licenses/adoption and actual native schemas remain action-specific prerequisites. Source reads are not binary qualification. The authored synthetic fixtures are not approved target databases/rules. S03.01A acquisition remains deferred.

Gitleaks and OSV lack complete native coverage ledgers. Opengrep omits skip information in some outputs and its pinned JSON conversion discards skipped-rule details. All need independent qualified coverage evidence. Native nonzero exit codes are preserved, including known finding exits; the current S01 result schema conservatively keeps those incomplete rather than inventing an exit-zero success.

OSV findings have no source-line location. Empty ranges mean unknown file-level location. Unrated advisory severity is encoded as Info with an explicit unrated gap, not a low-risk claim. Future target acceptance must not interpret this as clearance.

## Evidence interpretation

Normalized results are private evidence with original path/change/blob identities. They must pass through a separately approved report mediation step before being shared with any model or external recipient. Only the reviewer handoff is model-facing. Native report hashes, source mappings, raw stderr and secret-bearing originals remain private. The owned rule IDs are allowlisted; snippets, messages, Git author metadata and arbitrary scanner fields are discarded.

Both policies are bound: the S01 snapshot policy remains in its unchanged shared result schema, while the separate S02–S03 adapter-policy digest is retained in native execution/coverage inputs and the normalization envelope. One policy cannot silently replace the other.

The OSV parser records unrated advisory gaps; Gitleaks treats all detected secret-pattern findings as High pending independent analysis, not confirmed valid credentials. Opengrep's ERROR/WARNING labels map to High/Medium as a disclosed normalization convention, not a confirmed exploitability ranking. Confidence remains unknown. Every occurrence is retained with a distinct deterministic identifier; S04, not these adapters, owns later evidenced deduplication and target decisions.

## Cycle 1 source corrections

The seven findings from the first full independent source review have writer-owned source corrections in this revision. They are not independently closed until the complete corrected endpoint receives cycle 2 review. No unit/native tests were run while integrating them.

- All scanner normalizers reconstruct the adapter-specific exact invocation plan. Execution and external coverage evidence must bind plan_sha256; missing/stale/cross-mode receipts refuse. Historical receipts must not be edited to manufacture this field.
- Stdin findings and coverage name only the selected original item. Other selected snapshot items remain gaps. OSV result sources must declare the supported lockfile type.
- Virtual layouts bind the complete asset pin set, exact sanitized projection identity including alias inventory, and explicit OSV parser/target selection. Projection byte or alias changes invalidate the old identity.
- A semantic source/sink reference may be a local line number or an object with chunk_id and line, referencing any released line in the same handoff. Cross-file and cross-160-line flows are representable; foreign or unreleased references refuse. The full chunk/depth denominator remains mandatory.
- Exact approved OCR rules may contain ordinary newlines, carriage returns and tabs, but other control characters refuse. Candidate rule text still cannot alter approved-body equality or custom-source requirements.
- Paired baseline/head JSON with unchanged keys and weakened authorization values, plus actually selected candidate ignore/policy contents, are authored fixtures. Data-contract assertions do not claim a model reasoned about them or that native detection succeeded.
