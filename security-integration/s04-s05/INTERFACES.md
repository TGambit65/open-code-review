# Interface and evidence contract

All source is standard-library Python. The trusted host supplies the S01/S02–S03 packages on its explicit import path; this package never alters installed packages or process paths. Tests alone add the known sibling source directories.

- Subject fields bind repository_id/name, base_commit/head_commit, frozen_diff_sha256, snapshot_id, snapshot_policy_sha256, adapter_policy_sha256 and exact current source_sha256. `GatePolicy` is loaded only from an externally pinned ref supplied by the authorized host. Mandatory baseline adapters/severities cannot be removed. Required dataset names are policy-owned, not caller-selected empty coverage.
- The approved policy also pins a stable `history_scope_sha256` and the exact `prior_history_sha256`. A non-null history pin makes that previous document mandatory. Missing, substituted or differently scoped history cannot pass. Null is only an independently approved initial/no-prior-history assertion, never a candidate reset. Prior history retains its original source/policy identities; the current policy pins that already existing document, avoiding a circular policy/history hash dependency.
- S01 `Snapshot`, `Views`, `TrustedRef`, `TrustContext`, `parse_result` and coverage accounting are preserved unchanged. S02 adapter `Policy` is distinct from S01 policy. `Evidence.scanner` receives exact trusted expected pins and bounded normalized envelopes, not arbitrary raw tool formats or source-file fallback. The caller supplies original approved scanner views only to this trusted controller, never a model.
- The orchestration plan requires exactly five operation roles: OCR preview and rule, Opengrep files, one supported Gitleaks files/history/stdin operation, and OSV lockfiles. Both OCR operations must share the same snapshot, policy, tool, complete asset pins and sanitized projection. Four adapters do not mean four operations. Plans remain disabled data.
- OCR composition reconstructs sanitized projection and deep-review handoff. `approved-ocr-rule-body` binds the externally approved exact body to the pinned native JSON rule asset, adapter policy, snapshot, model bundle and a complete explicit `projection_suffixes` map. Map keys are exact opaque item IDs; values are supported suffixes without a leading dot. Host approval must confirm truthful file-type correspondence. There is no implicit `.txt` default and no relabel-everything-as-code fallback. Pinned native OCR excludes `.txt` and `.md`; such actual exclusions remain coverage gaps even with complete semantic records. The body digest is intentionally not confused with the whole rules-file digest. Native preview/rule reports/events remain parser inputs until an independent per-run attestation binds their exact Evidence hash and current qualification.
- Rejected scanner input and the separate rejected OCR preview/rule inputs retain digest-only identity, byte size and expected snapshot/policy scope. Scanner failures also retain validated expected pins. Exact input digests are bounded to 16 MiB per supplied byte string. Larger input retains its byte size and first-64-KiB digest with `full_input_identity_available=false` and `full_digest_unavailable_oversize`; this is explicitly incomplete provenance, never an exact full-input identity. Non-byte input has unknown identity. No rejected content is forwarded, and all these records remain parser errors.
- `Evidence.private_document`, `Assessment.private_decision` and finding-history documents may contain original paths and sensitive analysis metadata. They are private local records, not public reports. `reports.project(decision, evidence, views, snapshot, excerpt_ranges=())` requires the complete S01 Views and Snapshot, not a standalone ModelBundle. It binds snapshot identity, exact original scanner inputs, selected opaque IDs, model-bundle identity and each accepted evidence transformation digest before projecting locations or broker excerpts. Reusing `item-0000` does not establish content identity. A no-evidence report can show not-run with its bound Views but cannot release unbound excerpts. `render` accepts only the resulting PublicReport. Do not bypass `project` by constructing a PublicReport around raw data.
- Native evidence strings, model reasoning, rule bodies, candidate control values and claimed resolution never become policy or rendered markup. All schemas are local descriptive contracts; runtime validators are bounded and do not resolve remote schemas.
- UpdateSet is externally approved source identity/metadata, not acquired bytes or executable qualification. `verify_supplied_bytes` checks already supplied bytes without fetch/write/execute. The active database artifact/timestamp aggregate must exactly match OSV evidence's database pin. Prior sets are linked by exact digest and rollback remains visibly noncurrent.
- Qualified-run attestations are independently issued current evidence over the exact subject/policy, all four Evidence hashes, selected source identity/range denominator, current freshness receipt, per-adapter coverage, independent context assignment and S01/S02/S03 qualification receipts. Merely inventing hashes or unequal actor names is not independent evidence. Host custody/authority validation is a prerequisite that this data-only module cannot perform on its own.
- Finding correlation is explicit external evidence, not fuzzy deduplication. A finding keeps the highest retained severity until an independent exact-scope decision addresses every retained and current observation ID. Omitting a prior High finding, downgrading it to Low/Info or attaching a current-only resolution cannot clear it. Exceptions and resolutions bind the current subject/policy, authorized owner, reason, evidence, authorization, issue/expiry and finding-only scope. They cannot waive controls or hide coverage. Historical observations never satisfy current coverage. The public report exposes effective severity, current severity and blocking state separately; historical locations are withheld unless bound to the exact current evidence and snapshot. Current-run scoped decisions must be renewed for later subjects rather than treating prior receipt strings as authority.
- Computed target states and fixture qualification are separate. No return value grants native execution, sharing, root publication, external review, merge, installation or provider access. Existing unconditional execute refusals remain the final boundary.
- Workflow action records and review ledgers are pure proposed/observed state. Root owns durable storage and actual action reconciliation. A review ledger entry is a reconciled request/event identity, including origin/head/outcome/receipt, not a second request for each status poll. New-source merges must retain all required current-head gates even if they conflict with the one-review limit.
- A generic failed publication is an uncertain outcome, not permission to publish again. Preservation handoff requires reconciliation for failed, in-flight and uncertain attempts. Only the separate exact ActionRecord path can consider one supported retry after known nonexecution and materially new relevant unused authorization. These data objects never grant permission or perform the retry themselves.
