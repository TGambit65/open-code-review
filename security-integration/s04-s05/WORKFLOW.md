# Operator workflow and root handoff

1. Root binds the actual repository, base/head, branch, existing draft, payload scope and exact action holds. Use current verified facts; never reuse a stale branch head. One writer owns a coherent combined source endpoint.
2. Freeze every required/selected item, including fixtures and rollback. Conditional SARIF is explicitly not selected in S04–S05. Implement the whole endpoint before any checks or review; do not shrink it to get a test pass.
3. Seal exact additive source bytes and full file identities. Copied S00–S03 context is never replacement payload. A different-context independent reviewer reviews every path and relevant value. Resolve supported findings coherently and re-review the complete corrected endpoint.
4. Hand eligible source to root immediately in the same draft. Label untested, and review-pending when appropriate. Failed/unavailable review does not strand all eligible source. Held paths stay separate. Publication denial is not permission to use another route; failed, in-flight and uncertain publication outcomes must be reconciled before any repeat. A failed review and a failed publication are different states.
5. Root alone performs authorized publication, checks actual remote identities and saves the receipt. No workflow code here runs Git or contacts a repository. Preserve source below the batch-size target; never add filler. Track distinct paths for the entire PR. If the next coherent scope exceeds 300, hand root a dependent-draft plan rather than splitting security coherence or overfilling. Document genuine smaller final/dependency boundaries.
6. Only after the combined implementation, review and preservation sequence, run admitted offline tests and authorized local rendering. Native, asset, credential, provider and protected-target checks need their own current prerequisites. Preserve passed/failed/blocked/skipped/unrun outcomes. Correct source coherently, independently review changed source and preserve it before claiming a corrected current result.
7. Keep implementation, independent review, remote preservation, applicable validation and acceptance states separate. Only independently adopted qualification can clear acceptance. A clean report, source preservation, synthetic contract pass or exit zero does not clear a target.
8. At final batch freeze root reconciles completed, automatic, in-flight and uncertain CodeRabbit activity and exact current-head coverage. A ledger row is one reconciled request/automatic event, not one row for each poll. Prepare at most one included intentional request only when eligible and authorized. No per-sprint request, preservation-trigger lookup, duplicate intentional call, purchased capacity or protection changes. If corrected HEAD lacks a mandatory review and another intentional request conflicts with the limit, retain the conflict.
9. Merge is a root-only separate action tied to current change, authority, required current-head checks, current review, conflict state and all exact holds. A ready handoff is not a merge. No live scheduler, hooks, CI, AGENTS or unrelated work is changed.

Action records persist exact target/payload/action identity, actual outcome, attempts and used authorizations. An uncertain action always requires reconciliation. A generic failed result is not proof that nothing happened. After known nonexecution, only one retry per materially new relevant unused authorization/evidence may be considered by root through the explicit ActionRecord handoff. The data wrapper cannot determine legal relevance or grant permission; root applies the current policy and unchanged transcript evidence. Cancellation/denial stays held unless later valid authority resolves it.
