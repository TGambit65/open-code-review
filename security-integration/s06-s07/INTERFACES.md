# Interface and trust contracts

All product code uses the standard library and the preserved sibling S01/S02–S03/S04–S05 source interfaces. Product code does not modify import paths or installed packages; the trusted host supplies them explicitly. Test support alone loads the exact sibling fictional helper and inserts the known source directories.

## Disabled registry and disposition data

`registry.manifest()` is a static data description. Baseline operation roles remain OCR preview and rule, Opengrep files, one supported Gitleaks files/history/stdin operation, and OSV lockfiles. The existing S04 orchestrator still enforces identical OCR policy/snapshot/projection/tool/assets. Candidate names or booleans do not load executable modules. The ten research candidates have no implementation or supported runtime operation registered here.

`dispositions.load_catalog(raw, expected_sha256)` requires exact bytes and the frozen ten tool/task/decision identities. It permits only this freeze's defer/alternative/future-project outcomes with implementation_selected=false, registration_enabled=false and NOT_QUALIFIED. It returns a proposed Catalog, not adoption authority. Full records retain exact research pins, version/flag traps, license and data/network restrictions, missing current asset receipts, metrics plans and reopen conditions. Source and protocol locators are never opened by this parser.

## Combined offline evidence entrypoint

`evaluate_evidence(target, policy, evidence, snapshot, views, current_set, previous_set, now, catalog, excerpt_ranges=(), **evidence_options)` is a pure evaluation of supplied data. It calls the unchanged S04 assess path, including current GatePolicy/subject/history pins, four adapter Evidence identities and full Views/Snapshot transformation binding. A candidate catalog cannot weaken those policies, alter input scope, insert an optional adapter or bypass a refusal. Actual independent authority and qualification still come from the host, not matching strings/hashes in candidate code.

The returned Assessment contains a private baseline assessment, static registration bytes, a bounded disposition summary and the missing-coverage notice. `public_artifacts` returns security-report.json, security-report.md, security-report.html and security-integration-status.json as bytes in memory. Only the first three are representations of the same evidence document. The status artifact is a distinct explicit disabled/HELD notice. `receipts` gives exact byte identities and reports files_written=false/uploaded=false. The caller must not fabricate these containers as authority or expose the private baseline decision. No file writes or sharing occur.

An evaluated target status of pass is only the result of supplied evidence under policy. Integration is still disabled, native qualification is still held, and no target clearance or permission is granted by the wrapper. Native OCR preview/rule alone remains selection assistance, not deep semantic review. Actual TXT/Markdown exclusions and original range/redaction gaps remain incomplete.

## Independent stage inventory

`qualification.inventory(refs, context, source_sha256, scope_sha256, now)` accepts only separately authorized external TrustedRefs under the preserved TrustContext rules, not candidate-selected paths. Each receipt binds exact current source/scope, stage, actual action/result, actor, independent assignment/authority/artifact digests and location, issue/expiry and predecessor receipt hashes. Passed review/validation stages cannot omit or substitute prerequisites or precede their issue time. Preservation depends on implementation, not a clean review, so review failure does not strand eligible source. A final passed evidence review requires all earlier stage receipts and the exact set of their current hashes.

The result retains passed/failed/blocked/partial/unrun states and withholds raw locations/actors. It always retains qualified_native_entrypoint_not_implemented and HELD. It cannot replace original per-sprint acceptance, authentic kernel/native evidence, the CodeRabbit batch gate or explicit activation authority. SHA pins are identity checks, not signatures or proof of approval. No live receipts are supplied by this source.

## Traceability

`traceability.parse_ledger` is a bounded local parser for the complete original task/recommendation map. Frozen plan_ids constants retain original contract digests, dependencies, applicability and conditions. The ledger must include all 170 task IDs and all 23 exact recommendation mappings. An evidence locator does not assert its content is available or passed. `summary` explicitly says requirements_satisfied=false and qualification=HELD even when mapping_complete=true.

Traceability locators beginning with `security-integration/` are relative to the repository root. Other source/evidence locators are relative to this S06–S07 directory. Fragment labels identify the named JSON record or documented section. The parser treats all such locators as inert text and opens none of them.

All descriptive JSON schemas are local documentation only. Runtime validators do not fetch or resolve remote schemas. Prior source is not modified or requalified here.
